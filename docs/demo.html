· 容器以 root 运行或使用特权模式
位置 Dockerfile:2
证据 USER root
依据 OWASP Docker Security Cheat Sheet —— 容器应以非 root 用户运行；CIS Docker Benchmark 4.1（Create a user for the container）· 5.4（不启用 privileged）
建议 以 root 运行的容器，一旦被突破（应用漏洞 / 供应链投毒），攻击者直接拿到容器内最高权限，并可能借助内核漏洞逃逸到宿主。--privileged 更甚：几乎等于把宿主交出去。做法：Dockerfile 里加非 root 用户 + USER，去掉 --privileged，按需加 cap_drop。
· 权限策略出现通配符（Action/Resource 为 *）
位置 iam-policy.json:1
证据 "Action":"*"
依据 AWS IAM 最佳实践 —— 授予最小权限，避免在策略中使用通配符；CIS Benchmark · 最小权限原则
建议 `"Action": "*"` 或 `"Resource": "*"` 意味着这条凭据能做任何事、访问任何资源。一旦泄露（日志、CI、前端），攻击者拿到的是整个账号。改成按需列举具体 Action 与资源 ARN。

· CORS 允许所有来源
位置 server.js:1
证据 cors()
依据 OWASP — CORS 配置错误（WSTG-CLNT-11）；MDN — Access-Control-Allow-Origin
建议 `Access-Control-Allow-Origin: *` 让任意网站都能带着用户凭证调你的接口。如果同时开了 `Allow-Credentials: true`，浏览器会直接拒绝（但有些框架会「变通」成回显 Origin —— 那样更危险）。改成来源白名单。
· 申请了 admin / 全量 scope 的令牌
位置 .env:1
证据 SCOPE=admin repo
依据 OAuth 2.0 安全最佳实践（BCP）—— 应使用最小 scope；GitHub/云厂商文档均建议按需授权
建议 令牌申请了 `admin` / `*` / `repo`（GitHub 的 repo 含写权限）这类全量 scope，而代码只用到其中一小部分。令牌泄露时，攻击者拿到的是你申请的全部权限 —— 不是用到的部分。按实际调用的接口裁剪 scope。
