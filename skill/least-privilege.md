# 最小权限检查

查权限过宽：**容器跑 root、IAM 通配、CORS 全开、令牌申请 admin**。

## 一、为什么「权限过宽」比「有漏洞」更值得先修

漏洞是「可能被利用」，权限过宽是**「一旦被利用就全完了」**。

```
有漏洞 + 最小权限  → 攻击者拿到一个受限身份，能做的有限
有漏洞 + Action:*  → 攻击者拿到整个账号
```

**权限过宽是入侵的放大器。** 而且它没有任何症状 —— 系统照常运行，
直到出事那天你才发现那把钥匙能开所有的门。

## 二、它查什么

| 级别 | 项 | 依据 |
|---|---|---|
| 🔴 高 | **容器跑 root / `--privileged`** | OWASP Docker Cheat Sheet · CIS Docker Benchmark |
| 🔴 高 | **IAM `Action: *` / `Resource: *`** | AWS IAM 最佳实践 |
| 🟡 中 | **CORS 允许所有来源** | OWASP CORS 配置错误 |
| 🟡 中 | **令牌申请 admin / 全量 scope** | OAuth 2.0 安全最佳实践（最小 scope）|

## 三、怎么用

```bash
<cli 路径> --demo
<cli 路径> --list-rules
<cli 路径> --html r.html
```

## 四、边界

- **只查「明显过宽」的写法**：通配符、root、`*`、admin。
  「权限偏大但没用通配符」的情况需要人工评审，本工具看不出来。
- **不解析云厂商的实际生效策略**：IAM 有继承、条件、边界策略，
  本工具只看仓库里**字面写的**策略文件。
- **`cors()` 不带参数**在不同框架里语义不同（Express 的 `cors()` 确实是允许所有来源），
  但其它框架可能有别的默认值 —— 报出来请确认。
- **Dockerfile 可能是多阶段的**：`USER root` 出现在构建阶段（builder）通常无害，
  出现在最终阶段才有问题。本工具不区分阶段，需你判断。
- 与 `dsh-data-scan` / `dsh-cn-pipl-check` 分工：那些查数据，
  这个查**访问数据的权限**。

## 五、覆盖面

4 项，覆盖容器 / 云策略 / Web / 令牌四类常见的权限过宽。
